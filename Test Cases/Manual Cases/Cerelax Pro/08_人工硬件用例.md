### HW-MAN-006 运行中关闭/打开电脑蓝牙，设备能否继续工作
- **优先级**：P1
- **测试目的**：验证电脑侧蓝牙开关切换后，已连接的 Cerelax Pro 能否继续工作（继续出数据 / 恢复连接）。
- **流程与逻辑**：
  1. 连接 Cerelax Pro → init → 起流，确认数据正常到达。
  2. 关闭电脑蓝牙，观察 `isEnable`、`deviceState`、`isDataTransfering`、数据是否中断、是否触发错误/断开回调。
  3. 重新打开电脑蓝牙，观察 SDK 是否自动恢复连接与数据，或需重新 scan/connect。
- **预期结果**：关闭蓝牙时 SDK 能感知（`isEnable==False` 或收到关闭回调），已有连接按预期断连/报错而不崩溃；重新打开后能恢复，设备继续工作（重新出数据）。
- **有效性说明**：验证电脑蓝牙开关切换下 SDK 的恢复能力。
- **可自动化**：semi-auto
- **人工介入**：运行中人工关闭/打开电脑蓝牙。
- **测试结果**：待测试

## 系统级异常场景（SYS-ROB-*）

> 覆盖宿主系统事件对 BLE 连接与数据流的影响。多数为 semi-auto：程序负责连接、起流、观测与断言，人工只负责制造系统动作（蓝牙/WiFi/前后台/锁屏/旋转）。
> 动作未检测到时记 SKIP（而非 PASS/FAIL），避免「人没做」或 ROM 不支持被误判。

### SYS-ROB-001 扫描/连接中关闭蓝牙
- **优先级**：P0
- **测试目的**：验证扫描/连接过程中系统蓝牙被关闭时 SDK 的状态感知、连接处理与恢复能力。
- **流程与逻辑**：确认系统蓝牙已开启、设备在范围内 → 程序真实 `scan` + `connect` 到 `READY` → 人工关闭手机/平板蓝牙 → 等待 `isEnable=false`（最多 15s）→ 人工重新开启蓝牙 → 等待 `isEnable=true` → 程序主动断开，释放被自动重连占住的设备。
- **预期结果**：`isEnable` 由 `true → false → true`；关闭蓝牙后连接按预期断开/停止且不崩溃；恢复后控制器可继续扫描；用例结束不得把系统蓝牙留在关闭态。
- **有效性说明**：系统蓝牙是 BLE 前置；Android 关闭蓝牙后 `isEnable` 异步回传（约 1~2s），需轮询而非固定延时。动作前先断言蓝牙开启，避免「没关过蓝牙」也假 PASS。
- **可自动化**：semi-auto
- **人工介入**：关闭/开启手机（平板）蓝牙。
- **测试结果**：已实现（Demo 自动化，待真机验证）

### SYS-ROB-002 起流中关闭蓝牙后停止
- **优先级**：P0
- **测试目的**：验证起流过程中系统蓝牙关闭后，数据流停止且有明确因果证据。
- **流程与逻辑**：连接并 `startDataNotification`（确认 `isDataTransfering=true`，注册状态/错误回调）→ 人工关闭手机蓝牙 → 60s 内等待 `isDataTransfering=false` → 校验证据（`isEnable=false` / 收到 `DISCONNECTED` / 收到错误回调，任一即可）→ 人工开启蓝牙 → 主动断开释放设备。
- **预期结果**：起流停止；停止由蓝牙关闭引起（有上述任一证据）；不崩溃、不静默；蓝牙恢复后 SDK 可继续工作。
- **有效性说明**：仅看「流停了」不足以证明是蓝牙关闭导致，必须同时校验 `isEnable`/断连/错误回调证据；恢复蓝牙在断言前执行，避免失败时把系统留在关闭态。
- **可自动化**：semi-auto
- **人工介入**：关闭/开启手机（平板）蓝牙。
- **测试结果**：已实现（Demo 自动化，待真机验证）

### SYS-ROB-003 蓝牙重开后自动恢复
- **优先级**：P0
- **测试目的**：验证系统蓝牙关闭再开启后，已连接设备的数据流能自动恢复。
- **流程与逻辑**：确认系统蓝牙开启、设备在范围内 → 程序连接/init/起流 → 人工关闭蓝牙并确认流停止 → 人工重新开启蓝牙 → 观察 60s 内是否继续收到新样本（同一 profile，不重新 connect）。
- **预期结果**：关闭期间数据中断属正常；重新开启后 60s 内恢复出数（或由 `autoReconnect` 恢复连接后出数）；不崩溃。
- **有效性说明**：观测点是「动作后同一 profile 继续有新样本」，不是重新连接后的首包，避免把重连成功误当成恢复。
- **可自动化**：semi-auto
- **人工介入**：关闭/开启手机（平板）蓝牙。
- **测试结果**：已实现（Demo 自动化，待真机验证）

### SYS-ROB-004 WiFi 开关不影响 BLE 数据
- **优先级**：P1
- **测试目的**：验证 WiFi 开关切换不干扰 BLE 数据流。
- **流程与逻辑**：起流并确认首批数据到达 → 人工反复开关 WiFi（至少切换一次状态）→ 程序检测 WiFi 状态确实变化 → 观察动作后 10s 内是否继续收到新样本。
- **预期结果**：WiFi 切换期间及之后 BLE 数据持续到达；不崩溃；App 无 WiFi 服务或无法读取 WiFi 状态时记 SKIP。
- **有效性说明**：WiFi 与 BLE 共用 2.4GHz 射频，需验证共存不导致停流；未检测到 WiFi 切换则记 SKIP，避免假通过。
- **可自动化**：semi-auto
- **人工介入**：反复开关手机（平板）WiFi。
- **测试结果**：已实现（Demo 自动化，待真机验证）

### SYS-ROB-005 App 后台/前台与 onSuspend
- **优先级**：P0
- **测试目的**：验证 App 退后台再回前台（含 `onSuspend` 通知）后数据流不中断。
- **流程与逻辑**：起流并确认有数据 → 程序调用 `onSuspend` → 人工切到后台（回到桌面或切其他 App，**分屏不算**）再回前台 → 程序检测宿主 Activity 确实走过 `onStop` → 观察动作后 10s 内是否继续收到新样本。
- **预期结果**：切后台/回前台后数据持续到达或自动恢复；`onSuspend` 不导致崩溃/停流；未检测到真实后台切换时记 SKIP。
- **有效性说明**：只认 Activity 真的 `onStop`，分屏/悬浮窗不算后台，避免动作判定失真。
- **可自动化**：semi-auto
- **人工介入**：将 App 切后台再切回前台。
- **测试结果**：已实现（Demo 自动化，待真机验证）

### SYS-ROB-006 锁屏/解锁后数据恢复
- **优先级**：P1
- **测试目的**：验证锁屏/解锁后 BLE 数据流恢复能力。
- **流程与逻辑**：起流并确认有数据 → 人工锁屏数秒后解锁 → 程序通过 `KeyguardManager` 检测确实进入过锁屏 → 观察解锁后 10s 内是否继续收到新样本。
- **预期结果**：锁屏期间数据中断属正常；解锁后数据恢复；不崩溃；未检测到锁屏动作时记 SKIP。
- **有效性说明**：部分 ROM 锁屏会冻结后台进程，需验证 SDK 恢复能力；用系统锁屏状态做动作判定，避免假通过。
- **可自动化**：semi-auto
- **人工介入**：锁屏数秒后解锁。
- **测试结果**：已实现（Demo 自动化，待真机验证）

### SYS-ROB-007 旋转/分屏后数据恢复
- **优先级**：P1
- **测试目的**：验证屏幕旋转或进入/退出分屏后 BLE 数据流不中断。
- **流程与逻辑**：起流并确认有数据 → 人工旋转屏幕或进入分屏再切回（系统关闭自动旋转时直接进分屏）→ 程序检测屏幕方向或多窗口状态变化 → 观察动作后 10s 内是否继续收到新样本。
- **预期结果**：旋转/分屏过程中及之后数据持续到达或恢复；不崩溃；未检测到方向/多窗口变化时记 SKIP。
- **有效性说明**：Activity 重建/配置变化可能影响回调注册，需验证数据回调不丢失；用方向/多窗口状态做动作判定。
- **可自动化**：semi-auto
- **人工介入**：旋转屏幕或进入/退出分屏。
- **测试结果**：已实现（Demo 自动化，待真机验证）

### SYS-ROB-008 权限撤销与恢复
- **优先级**：P0
- **测试目的**：验证蓝牙权限（`BLUETOOTH_SCAN` / `BLUETOOTH_CONNECT`）被撤销后的拒绝行为与恢复能力。
- **流程与逻辑**：运行前撤销 `BLUETOOTH_SCAN` / `BLUETOOTH_CONNECT` → 尝试扫描/连接 → 确认被拒绝且 App 不崩溃 → 重新授权 → 确认扫描/连接恢复。
- **预期结果**：无权限时扫描/连接失败或被拒绝，有明确错误而非静默；App 不崩溃；重新授权后功能恢复。
- **有效性说明**：Android 12+ 蓝牙权限为运行时权限，权限缺失必须在 SDK 边界被正确处理。
- **可自动化**：manual
- **人工介入**：在系统设置中撤销/恢复蓝牙权限。
- **测试结果**：已登记（Demo 自动化，人工执行）

- **有效性说明**：真实用户场景下的系统级干扰，难以稳定脚本化，保留人工观测。
- **可自动化**：manual
- **人工介入**：制造来电/通知/系统弹窗。
- **测试结果**：已登记（Demo 自动化，人工执行）
