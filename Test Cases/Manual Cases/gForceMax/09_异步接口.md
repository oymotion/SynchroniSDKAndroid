# gForceMax 异步接口用例（ASYNC-*）

> **Android 口径**：Android **没有** `asyncXxx` 命名。等价能力分两类：
> 1. **suspend 扩展**：`controller.scan(timeoutMs)`、`profile.init(...)`、`setParam/getParam`、
>    `getBatteryLevel()`、`startDataNotification()/stopDataNotification()`、
>    `controller.multiStartDataNotification(...)/multiStopDataNotification(...)`，在 `runBlocking` 中直接调用；
> 2. **CompletableFuture**：`profile.connectAsync()`/`disconnectAsync()`（另有
>    `initAsync/setParamAsync/getParamAsync/getBatteryLevelAsync/startDataNotificationAsync/stopDataNotificationAsync`），
>    用 `.get(timeout, TimeUnit.MILLISECONDS)` 等待并超时保护。
> Android 无 Python asyncio 事件循环，suspend 与 CompletableFuture 可自由混用（见 ASYNC-FUNC-010）。
> 多设备用例需 ≥2 台，缺设备则 SKIP。

### ASYNC-FUNC-001 异步扫描返回设备列表
- **优先级**：P0
- **测试目的**：验证异步扫描（Android：`suspend scan`）。
- **流程与逻辑**：`runBlocking { controller.scan(5000) }`，遍历结果检查是否含 gForceMax（name 以 `gForceMax` 开头且 mac 非空）。
- **预期结果**：返回 `List<BleDevice>`，含 gForceMax；与同步路径结果一致（同一设备 MAC 相同）。
- **有效性说明**：Android 的 `scan` 本身就是挂起函数，不存在独立的 async 扫描入口。
- **可自动化**：auto
- **人工介入**：无。
- **测试结果**：待测试

### ASYNC-FUNC-002 connectAsync 成功/失败
- **优先级**：P0
- **测试目的**：验证异步连接。
- **流程与逻辑**：`requireSensor(mac)` 后 `profile.connectAsync().get(READY_TIMEOUT_MS, MILLISECONDS)`，观察返回与 `getDeviceState()`；再对无效 MAC 的 profile 调用观察失败。
- **预期结果**：成功返回 `true` 并到 `READY`；失败返回 `false` 或抛 `ExecutionException`（原因可读），不崩溃。
- **有效性说明**：`connectAsync()` 返回 `CompletableFuture<Boolean>`；超时未完成用 `getOrNull` 记录为失败，不得无限阻塞。
- **可自动化**：auto
- **人工介入**：无。
- **测试结果**：待测试

### ASYNC-FUNC-010 async/sync 混用行为明确
- **优先级**：P1
- **测试目的**：验证 CompletableFuture 与 suspend 混用时的状态一致性。
- **流程与逻辑**：用 `connectAsync()`（CompletableFuture）连接 → 用 suspend `init()` → suspend `startDataNotification()` → suspend `stopDataNotification()` → suspend `disconnect()`，全程收集状态迁移与返回值；再反向走一遍"suspend connect + `disconnectAsync`"。
- **预期结果**：两种调用方式可自由混用，无事件循环冲突；状态迁移正确（`CONNECTING→CONNECTED→READY→DISCONNECTED`），返回值与纯 suspend 路径一致。
- **有效性说明**：Android **无** Python"协程内调用同步接口被拒绝/返回 None"的限制，源用例的拒绝断言不适用；本用例改判"混用一致性"。若出现状态错乱或异常，判 FAIL。
- **可自动化**：auto
- **人工介入**：无。
- **测试结果**：待测试

### ASYNC-FUNC-011 多设备异步同步起流（需 ≥2 台）
- **优先级**：P1
- **测试目的**：验证多设备同步起流（Android：回调式 `multiStartDataNotification`）。
- **流程与逻辑**：两台 init 后调 `controller.multiStartDataNotification(profiles, 30000, 5, 3) { results, errors -> }`，等待回调，检查逐台结果与两台 `isDataTransfering()`。
- **预期结果**：`results` 覆盖两台且均为 `true`，`errors` 为空，两台均起流。
- **有效性说明**：Android 无 `asyncMultiStartDataNotification`，等价为回调式 `multiStartDataNotification`（需 `suspendCancellableCoroutine` 包装等待）；缺第二台 SKIP。
- **可自动化**：auto
- **人工介入**：无（需 ≥2 台设备）。
- **测试结果**：待测试
