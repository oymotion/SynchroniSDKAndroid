# gForceMax 连接与状态机用例（DEV-SM-*）

> **Android 口径**：`SensorProfile` 由 `controller.requireSensor(mac)` 获取；状态用
> `getDeviceState(): Int` 与 `DeviceState.DISCONNECTED/CONNECTING/CONNECTED/READY` 常量比较，
> 状态名用 `DeviceState.nameOf(state)`。状态回调为 `setOnStateChangeListener { profile, state -> }`，
> 错误回调为 `setOnErrorListener { profile, msg -> }`，自动重连回调用
> `setOnAutoReconnectListener { profile, restore, answer -> answer.answer(bool) }`。
> `connect()/disconnect()/init()/startDataNotification()/stopDataNotification()` 为 suspend 扩展、返回 `Boolean`。
> 下列用例默认针对单台 gForceMax（identity `9AA7`）执行。

### DEV-SM-001 connect 成功，状态迁移 Disconnected→Connecting→Connected→Ready
- **优先级**：P0
- **测试目的**：验证连接成功与状态迁移序列。
- **流程与逻辑**：`requireSensor(mac)` 后注册 `setOnStateChangeListener`，调用 `connect()`，收集每次状态到列表；轮询直到 `getDeviceState()==DeviceState.READY`。
- **预期结果**：`connect()` 返回 `true`；状态序列包含 `CONNECTING→CONNECTED→READY` 且顺序正确；最终 `getDeviceState()==READY`、`isReady()==true`。
- **有效性说明**：连接是后续操作前提；迁移顺序错误会导致指令在错误状态下发送。`CONNECTING` 可能因连接过快未被观测到，允许缺失但不得乱序。
- **可自动化**：auto
- **人工介入**：无。
- **测试结果**：待测试

### DEV-SM-002 connect 失败返回 false 并回调原因
- **优先级**：P1
- **测试目的**：验证连接失败路径可观测。
- **流程与逻辑**：先扫描获取目标 MAC → 人工关闭设备电源或移出范围 → `requireSensor(mac)` → 注册 `setOnErrorListener` → `connect()`（可能阻塞至连接超时）。
- **预期结果**：`connect()` 返回 `false`；`setOnErrorListener` 收到非空错误信息；`getDeviceState()!=READY`。
- **有效性说明**：失败可观测、不静默；Android 用 `setOnErrorListener` 替代 Python `onErrorCallback`。
- **可自动化**：semi-auto
- **人工介入**：人工关闭设备电源或移出范围。
- **测试结果**：待测试

### DEV-SM-003 非目标设备不误连接
- **优先级**：P1
- **测试目的**：验证不误连其它设备。
- **流程与逻辑**：`scan()` 后按 `TestConfig.matchesTarget()` 筛出 gForceMax（MAC `BC:93:2A:3F:9A:A7` / identity `9AA7`），记录其余设备 MAC；只对目标 MAC `requireSensor` + `connect()`，再查 `getConnectedSensors()`。
- **预期结果**：连接集合仅含目标 MAC；扫描到的其它 BLE 设备不会被自动连接。
- **有效性说明**：防止串设备。若环境中只有一台 BLE 设备，本用例的"排除"断言退化为"未误连其它设备"，仍应通过；无任何其它设备时记 SKIP。
- **可自动化**：auto
- **人工介入**：无。
- **测试结果**：待测试

- **有效性说明**：断开干净、状态正确；Android 无显式 `DISCONNECTING` 常量时以实际序列为准，不臆造状态。

- **有效性说明**：避免传输中硬断开导致资源问题；不单独调用 `stopDataNotification()`。

### DEV-SM-006 Ready 前不发送命令

- **有效性说明**：确认 SDK 内部状态门控；`setParam` 成功只认 `"OK"`，`Error` 开头/异常均视为被拒绝。

### DEV-SM-007 BleDevice 的 name/mac/RSSI 与扫描一致

### DEV-SM-008 autoReconnect 默认开启时异常断链自动恢复
- **优先级**：P0
- **测试目的**：验证自动重连恢复链路。
- **流程与逻辑**：`setAutoReconnect(true)` → 连接、init、起流 → 人工断电/移出范围 → 恢复供电/回到范围 → 观察状态是否回到 Ready、是否自动恢复起流（`isDataTransfering()` 与数据回调）。
- **预期结果**：恢复后重新进入 Ready 并恢复数据通知；`setOnAutoReconnectListener` 被调用，`restore` 反映是否恢复上次会话。
- **有效性说明**：异常恢复核心，长稳/移动场景关键；Android 无 `getAutoReconnect()` getter，默认值以行为验证为准。
- **可自动化**：semi-auto
- **人工介入**：人工断电/移出范围后恢复，观察恢复过程（`manualPauseSeconds` 窗口）。
- **测试结果**：待测试

### DEV-SM-010 setOnAutoReconnectListener(restore=true) 自定义恢复

- **有效性说明**：恢复逻辑可定制；`answer` 为回调提供的应答对象（非 Python 的函数入参）。

### DEV-SM-014 setOnDeviceInfoUpdateListener 触发与就地更新

### DEV-SM-015 disconnect 后重新 scan 可再次发现设备
- **优先级**：P1
- **测试目的**：验证主动断开后，同一台设备可被再次扫描发现。
- **流程与逻辑**：`scan()` 匹配目标并记录 MAC → `requireSensor` → `connect()` 到 Ready → `disconnect()` 到 Disconnected → 重新 `scan(timeoutMs)`（带重试，按 MAC 精确匹配同一台设备）。
- **预期结果**：断开后重新扫描结果包含同一 MAC。
- **有效性说明**：若断开后 scan 找不到该设备（被 SDK 当作"已连接/已知"而过滤），会影响重连与多设备管理，属缺陷。重试上限 2 次，间隔 `scanRetryIntervalMs`。
- **可自动化**：auto
- **人工介入**：无（设备上电在范围内为运行前置）。
- **测试结果**：待测试

### DEV-SM-016 isAutoReconnecting() 属性反映重连过程
- **优先级**：P1
- **测试目的**：验证自动重连进行中状态查询。
- **流程与逻辑**：`setAutoReconnect(true)` → 连接起流 → 断电/移出范围触发自动重连 → 重连窗口内轮询 `isAutoReconnecting()` → 恢复 Ready 后再读；另测未连接/正常 Ready/主动断开三态。
- **预期结果**：重连进行中 `isAutoReconnecting()==true`；恢复后及未断链、主动断开、未连接时均为 `false`。
- **有效性说明**：区分"断链"与"重连进行中"，便于上层提示与去抖；"未断链恒为 false"部分可 auto，重连窗口部分需人工断电。
- **可自动化**：semi-auto
- **人工介入**：人工断电/移出范围后恢复。
- **测试结果**：待测试

### DEV-SM-017 onAutoReconnectingStateChange 回调触发（sensor, is_auto_reconnecting）
- **优先级**：P1
- **测试目的**：验证自动重连状态变化回调（**保留源 ID，Android 不适用**）。
- **流程与逻辑**：Android AAR 未提供 `onAutoReconnectingStateChange`/`setOnAutoReconnectingStateChangeListener`；不注册该回调。等价观测改为 `isAutoReconnecting()` 轮询（见 DEV-SM-016）。
- **预期结果**：不适用。Android 无"重连状态变化"专用回调，重连状态通过 `isAutoReconnecting()` 查询与 `setOnAutoReconnectListener` 感知。
- **有效性说明**：本用例在 Android 侧标 `@Ignore("Android 无 onAutoReconnectingStateChange 回调，改用 isAutoReconnecting() 轮询（DEV-SM-016）")`。
- **可自动化**：manual
- **人工介入**：无（不执行）。
- **测试结果**：待测试

### DEV-SM-018 配对/bond 信息持久与免配对重连
- **优先级**：P2
- **测试目的**：验证设备配对信息在 App 重启、断开重连后仍然有效，重连不重复弹配对框。

- **预期结果**：已配对设备重连无需重新配对；不弹配对框或由系统自动完成；bond 信息在 App 重启后仍有效。
- **有效性说明**：依赖 Android 系统 bond 状态与设备固件行为，需人工在系统蓝牙设置中确认/删除配对信息。
- **可自动化**：manual
- **人工介入**：在系统蓝牙设置中查看、删除配对信息，配合重启 App。
- **测试结果**：已登记（手工执行）

### DEV-SM-019 广播间隔与重连退避

- **预期结果**：广播间隔符合固件定义；SDK 重连尝试逐步退避，不持续高频重连；设备恢复后能连上。
- **有效性说明**：需要抓包或系统蓝牙日志，纯自动化难以稳定判定广播间隔。
- **可自动化**：manual
- **人工介入**：设备上下电，配合抓包/日志观察。
- **测试结果**：已登记（手工执行）

### DEV-SM-020 isAutoReconnecting 非恢复态恒为 false
- **优先级**：P1
- **测试目的**：验证自动重连状态只在恢复流程中为 `true`，不会常驻导致 UI 误提示。

- **预期结果**：未进入自动重连流程时恒为 `false`；仅在恢复流程中为 `true`；流程结束后回到 `false`。
- **有效性说明**：该状态用于上层 UI 提示，常驻 `true` 会误导用户。
- **可自动化**：auto
- **人工介入**：无（设备关机步骤可由用例控制）
