# gForceMax 底层接口与边界补充用例（MISC-*）

> **Android 口径**：补齐覆盖率审计中未覆盖的接口。Android AAR 中：
> - **无** `hasDeviceFoundCallback` 查询（只有 `setOnScanResultListener`）；
> - **无** `SensorData` 序列化/复用接口（`to_flatbuffers`/`from_flatbuffers`/`from_flatbuffers_pooled`/`clear`/`reset`）
>   与 `Sample.reset`（`SensorData`/`Sample` 不可变，仅 `clone()`）；
> - **无** `submit(fn, *args)` 公开 API（后台执行用 `connectAsync()` 等 `CompletableFuture` 或 Kotlin 协程）；
> - `DeviceState.INVALID` 为 Java int 常量，`DeviceInfo` 为 public 字段。

### MISC-FUNC-008 DeviceInfo 能力字段完整性
- **优先级**：P1
- **测试目的**：验证 `getDeviceInfo()` 返回的能力字段完整且合法。
- **流程与逻辑**：Ready + init 后调 `getDeviceInfo()`，逐一读取：`modelName`、`firmwareVersion`、`deviceName`，各模态通道数 `emgChannelCount`/`accChannelCount`/`gyroChannelCount`/`angleChannelCount`/`magChannelCount`/`imuChannelCount`/`impeChannelCount`/`eegChannelCount`/`ecgChannelCount`/`ppgChannelCount`/`spo2ChannelCount`/`brthChannelCount`，以及对应 `xxxSampleRate`。
- **预期结果**：字段齐全，通道数与采样率均 `≥0`；按 spec：`emgChannelCount==8`、`imuChannelCount==13`、`impeChannelCount==8`、`eeg/ecg/brth/ppg/spo2/mag/angle==0`；`modelName` 可能上报 `gForceUltra`（已知固件现象，spec 仍按 `gForceMax.json` 加载，不判 FAIL）。
- **有效性说明**：能力字段是数据流/参数用例的判定依据，必须可靠；偏离 spec 标 supported 的通道数判 FAIL，标 unsupported 却 `>0` 亦判 FAIL。
- **可自动化**：auto
- **人工介入**：无。
- **测试结果**：待测试

### MISC-FUNC-010 后台执行 connect/disconnect（Android 等价：connectAsync/disconnectAsync）
- **优先级**：P1
- **测试目的**：验证异步包装的 connect/disconnect 不阻塞调用方，且结果/状态迁移正确。
- **流程与逻辑**：`requireSensor(mac)` 后调 `profile.connectAsync()` 记录返回（应立即得到 `CompletableFuture`，不阻塞）→ `.get(READY_TIMEOUT_MS, MILLISECONDS)` 取回 `true` → 断言 `getDeviceState()==READY`；再 `disconnectAsync().get(...)` 取回 `true` → 断言 `DISCONNECTED`。
- **预期结果**：调用 `connectAsync()` 立即返回 Future；结果 `true`、状态迁移正确；`disconnectAsync()` 同样非阻塞且结果正确。
- **有效性说明**：源用例的 `submit(sensor.connect)` 官方用法在 Android 对应 `connectAsync()`；两者都用于避免冻结调用方（UI）线程。与 ASYNC-FUNC-002/003 的区别：本用例额外断言"调用立即返回（不阻塞调用线程）"。
- **可自动化**：auto（需待测设备上电在范围内）
- **人工介入**：无。
- **测试结果**：待测试
