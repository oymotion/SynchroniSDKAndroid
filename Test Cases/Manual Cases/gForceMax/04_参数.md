# gForceMax 参数用例（PARAM-*）

> **Android 口径**：`SensorProfile.setParam(key: String, value: String): String` 与
> `getParam(key: String): String?` 均为 suspend 扩展；`setParam` **成功只认返回值 `"OK"`**，
> 以 `Error` 开头 / `Not supported` / 抛异常均视为被拒绝。能力判定以 `getDeviceInfo()` 的
> `ChannelCount>0` 为准，**不以** `getParam("NTF_XXX")=="ON"` 判定支持。
> 采样率参数（`Test Cases/Automation/device_specs/gForceMax.json`）：
> `EMG_SAMPLE_RATE` 500|1000（默认 1000）、`IMU_SAMPLE_RATE` 50|100|200（默认 50，以设备回读为准）、
> `IMPEDANCE` 固定 1（settable=false，coStream=NTF_EMG）；滤波 `FILTER_50HZ/60HZ/HPF/LPF` 四项均支持。

### PARAM-FUNC-001 每个 NTF_* 键 ON/OFF 返回 OK，getParam 一致
- **优先级**：P0
- **测试目的**：验证数据流开关。
- **流程与逻辑**：对支持的键 `NTF_EMG`/`NTF_GEST`/`NTF_IMU` 逐一 `setParam("ON")`、`getParam("NTF")` 核对、再 `setParam("OFF")` 核对；对无独立开关的 `NTF_GFORCE_ACC`/`NTF_GFORCE_GYRO`/`NTF_GFORCE_EULER`/`NTF_GFORCE_QUAT` 记录 `getParam` 返回 `Not supported`；对 `NTF_MAG`/`NTF_ANGLE_DATA`/`NTF_EEG`/`NTF_ECG`/`NTF_BRTH`/`NTF_PPG`/`NTF_SPO2` 按 `ChannelCount` 判定为不支持，`setParam` 应返回 `Not supported`/`Error...`。
- **预期结果**：三个支持键 `setParam` 返回 `"OK"` 且 `getParam("NTF")` 中对应项状态一致；不支持键不被静默接受（不得返回 `"OK"`）；`NTF_IMPEDANCE` 无独立开关，随 `NTF_EMG` 起停。
- **有效性说明**：参数读写一致；`setParam` 的流键与 `DataType` 常量名是两套空间，`NTF_ANGLE_DATA` 仅用于 `getDataType()` 匹配，不可当作 setParam 键。
- **可自动化**：auto
- **人工介入**：无。
- **测试结果**：待测试

- **有效性说明**：spec 声明四项滤波均支持，任一返回非 `"OK"` 判 FAIL。
- **可自动化**：auto

### PARAM-FUNC-003 NTF_IMU 联动四个 NTF_GFORCE_*（不适用 gForceMax）
- **优先级**：P2
- **测试目的**：验证 IMU 主开关联动。
- **流程与逻辑**：gForceMax 无 `NTF_GFORCE_*` 独立开关（acc/gyro/euler/quat 打包进 `NTF_IMU` 聚合流）。验证方式改为：`setParam("NTF_IMU","OFF")` 后确认 `NTF_ACC/NTF_GYRO/NTF_EULER/NTF_QUATERNION/NTF_IMU` 均无数据；`ON` 后仅 `NTF_IMU` 聚合流有数据。
- **预期结果**：无独立子开关；聚合开关可整体起停四类数据，不产生独立 `NTF_GFORCE_*` 数据流。
- **有效性说明**：源用例的"主/子开关一致性"在 gForceMax 退化为"聚合开关整体生效"；`setParam("NTF_GFORCE_ACC", ...)` 预期返回 `Not supported`。
- **可自动化**：auto
- **人工介入**：无。
- **测试结果**：待测试

### PARAM-FUNC-004 EMG_SAMPLE_RATE 设置 500/1000 + 非法值 750
- **优先级**：P0
- **测试目的**：验证 EMG 采样率设置（500/1000 两档，默认 1000）。
- **流程与逻辑**：`connect` 到 `DeviceState.READY` 并 `init` 后、未做任何 `setParam("EMG_SAMPLE_RATE")` 之前，首次 `getParam("EMG_SAMPLE_RATE")` 应为上电默认 `1000`；`getParam("EMG_SAMPLE_RATE_LIST")` 应返回含 `500`/`1000` 的管道分隔列表；逐一 `setParam("EMG_SAMPLE_RATE","500"/"1000")` 后读回一致；`setParam("EMG_SAMPLE_RATE","750")` 与空串应被拒绝。
- **预期结果**：500/1000 设置成功并读回一致，上电默认 1000；非法值 750 与空串返回 `Error...`（或抛受控异常）。
- **有效性说明**：EMG 采样率参数读写一致 + 非法输入容错；测 1000Hz 前先 `setParam("NTF_GEST","OFF")` 规避已知算力冲突。
- **可自动化**：auto
- **人工介入**：无。
- **测试结果**：待测试

### PARAM-FUNC-005 EEG_SAMPLE_RATE 不支持值返回 Error（能力反向）

- **可自动化**：auto
- **人工介入**：无。

### PARAM-FUNC-007 起流中修改参数自动停流重起并生效

- **有效性说明**：动态配置能力；若 SDK 要求先 `stopDataNotification()` 才可改参，应返回明确错误而非静默无效，并在用例中记录实际行为。
