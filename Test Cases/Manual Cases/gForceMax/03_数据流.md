# gForceMax 数据流用例（DATA-*）

> **Android 口径**：`SensorProfile.init(packageSampleCount, initTimeoutMs, powerRefreshIntervalMs)`、
> `startDataNotification()`/`stopDataNotification()` 均为 suspend 扩展、返回 `Boolean`；数据回调为
> `setOnDataListener { profile, dataList -> }`。`SensorData` 元数据为**属性**（`deviceMac`/`dataType`/
> `sampleRate`/`channelCount`/`sampleCount`/`channelMask`/`lostPackageCount`/`startSampleIndex`），
> `isDataValid()`/`isChannelEnabled(ch)`/`isLost(ch,i)`/`getData(ch,i)`/`getChannelSample(ch,i)`/
> `getSampleIndex(ch,i)`/`getImpedance(ch,i)`/`getSaturation(ch,i)` 为**方法**。`DataType` 为 Java int 常量
> （`DataType.NTF_EMG` 等），按 `getDataType()` 分桶统计，**不得跨流累加通道**。

## 已固化能力（单一事实来源：`Test Cases/Automation/device_specs/gForceMax.json`）

> 判定口径：`getDeviceInfo()` 对应 `ChannelCount > 0` 才执行；**不以** `getParam("NTF_XXX")=="ON"` 判定支持。
> spec 标 supported 的流收不到数据即 FAIL；标 unsupported 的流产出数据即 FAIL；不支持的能力记 SKIP。

| 流（DataType） | spec channels | 期望 | 说明 |
|----------------|---------------|------|------|
| `NTF_EMG` | 8 | 支持 | 8 通道肌电，采样率 500\|1000（默认 1000） |
| `NTF_GEST` | 1 | 支持 | 固定约 15.625Hz，无采样率参数 |
| `NTF_IMU` | 13 | 支持 | 聚合流：acc 0-2 / gyro 3-5 / euler 6-8 / quat 9-12 |
| `NTF_GFORCE_ACC/GYRO/EULER/QUAT` | 0 | 不支持 | 无独立开关，`getParam` 返回 `Not supported` |
| `NTF_IMPEDANCE` | 8 | 支持 | 固定约 1Hz，需与 `NTF_EMG` 同起（coStream） |
| `NTF_MAG` / `NTF_ANGLE_DATA` | 0 | 不支持 | 无独立开关/无磁力计 |
| `NTF_EEG` / `NTF_ECG` / `NTF_BRTH` / `NTF_PPG` / `NTF_SPO2` | 0 | 不支持 | ChannelCount 恒 0 |

### DATA-FUNC-005 各 DataType 流能收到对应 SensorData
- **优先级**：P0
- **测试目的**：验证 gForceMax 支持的数据流类型。
- **流程与逻辑**：按 spec 逐流开关并起流，统计 `getDataType()`：
  1. `setParam("NTF_EMG","ON")` + `setParam("NTF_IMU","ON")` + `setParam("NTF_GEST","ON")` → 起流，分别累计 `NTF_EMG`/`NTF_IMU`/`NTF_GEST` 的批次数与样本数；
  2. 阻抗随 EMG 同起（无独立开关）：确认 `NTF_IMPEDANCE` 数据在 `NTF_EMG` 起流后出现；
  3. 对 unsupported 流（EEG/ECG/BRTH/PPG/SPO2/MAG/ANGLE）尝试 `setParam(...,"ON")`，记录返回并确认无对应 `getDataType()` 数据；
  4. `NTF_GFORCE_ACC/GYRO/EULER/QUAT` 无独立开关，不单独起流，其数据只应出现在 `NTF_IMU` 聚合流中。
- **预期结果**：`NTF_EMG`(8ch)、`NTF_GEST`(1ch)、`NTF_IMU`(13ch)、`NTF_IMPEDANCE`(8ch) 均收到数据且 `channelCount` 与 spec 一致；unsupported 流 `setParam` 返回 `Not supported`/`Error...` 且无数据；任一 supported 流收不到数据判 FAIL。
- **有效性说明**：逐模态验证真实能力，避免遗漏/误判；能力以 `DeviceInfo` 的 `ChannelCount>0` 为准，不以 `getParam=="ON"` 判定。
- **可自动化**：auto
- **人工介入**：若手势流需真实手势才产生有效 ID，可人工做手势；仅验证"有数据"时无需人工。
- **测试结果**：待测试

### DATA-FUNC-011 NTF_GEST 与 NTF_EMG 共存及高采样率算力冲突观测
- **优先级**：P1
- **测试目的**：验证手势流与肌电流共存，并观测 EMG 1000Hz 下的算力冲突（gForceMax 重点）。
- **流程与逻辑**：
  1. `setParam("NTF_EMG","ON")` + `setParam("NTF_GEST","ON")`，`setParam("EMG_SAMPLE_RATE","500")`，起流 10s，分别统计 `NTF_EMG`/`NTF_GEST` 数据；
  2. 停流后 `setParam("EMG_SAMPLE_RATE","1000")`，重复起流 10s，记录两流数据与掉速/丢包；
  3. 再执行 `setParam("NTF_GEST","OFF")` 后测 EMG 1000Hz，作为对照。
- **预期结果**：500Hz 下两流可共存且均有数据；1000Hz 下若出现 GEST 无数据/EMG 掉速，记录为"已知算力冲突现象"，不判 FAIL；关闭 GEST 后 EMG 1000Hz 应恢复正常速率。**不做"两者互斥"断言**（gForceMax 两流均 supported）。
- **有效性说明**：源用例的"传统设备互斥"结论不适用于 gForceMax；冲突是当前固件的已知现象，不是永久硬约束，不得写成永久断言。测 EMG 高采样率前统一先 `setParam("NTF_GEST","OFF")`。
- **可自动化**：auto
- **人工介入**：无（如需有效手势 ID 可人工做手势）。
- **测试结果**：待测试
