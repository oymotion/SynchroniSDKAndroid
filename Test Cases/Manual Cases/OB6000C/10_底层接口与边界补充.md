# OB6000C 底层接口与边界补充用例（MISC-*）

> 补齐覆盖率审计中未覆盖的接口：扫描结果回调、`DeviceState.INVALID`、`DeviceInfo` 能力字段、`SensorData.startSampleIndex`。
> 注：`SensorData` 序列化接口（`to_flatbuffers/from_flatbuffers/from_flatbuffers_pooled`）、复用接口（`clear/reset`）与 `Sample.reset` 在 SDK 1.3.0 已移除；Android AAR 亦不提供，MISC-002~005 标记「接口已移除」。
> Python 专属的 `hasDeviceFoundCallback`、`submit()` 在 Android AAR 无对应实现，MISC-001/009/010 按「不适用」处理并给出等价能力说明。

### MISC-FUNC-007 DeviceState.INVALID 状态
- **优先级**：P1
- **测试目的**：验证 `INVALID` 状态的触发与语义。
- **流程与逻辑**：构造非法/异常场景（如 `SensorController.terminate()` 后继续使用旧 `SensorProfile`、异常初始化后读取状态、设备信息缺失）观察是否进入 `DeviceState.INVALID`，确认 SDK 不崩溃、可恢复。
- **预期结果**：异常场景下状态可落入 `DeviceState.INVALID`（`DeviceState.nameOf()` 返回 `INVALID`），且不崩溃；可通过重新 `requireSensor`/`connect` 恢复。
- **有效性说明**：补齐状态机唯一未覆盖的常量；Android 无 `DeviceStateEx`，统一用 `DeviceState.INVALID`。
- **可自动化**：semi-auto
- **人工介入**：人工制造异常场景（如 terminate 后继续操作）。
- **测试结果**：待测试

### MISC-FUNC-008 DeviceInfo 能力字段完整性
- **优先级**：P1
- **测试目的**：验证 `getDeviceInfo()` 返回的能力字段完整且合法。
- **流程与逻辑**：READY + `init` 后调 `getDeviceInfo()`（或用 `fetchDeviceInfo()` suspend 刷新），逐一读取 public 字段：
  `modelName`、`firmwareVersion`、`eegChannelCount`、`emgChannelCount`、`ecgChannelCount`、`brthChannelCount`、`accChannelCount`、`gyroChannelCount`、`eulerChannelCount`、`quatChannelCount`、`imuChannelCount`、`magChannelCount`、`angleChannelCount`、`impeChannelCount`、`ppgChannelCount`、`spo2ChannelCount`、`gestChannelCount`，以及对应的 `*SampleRate`。
- **预期结果**：字段齐全且 `ChannelCount >= 0`、`SampleRate >= 0`；OB6000C 实测：`eegChannelCount=32`、`impeChannelCount=32`、`imuChannelCount=13`、`acc/gyro/euler=3`、`quat=4`、`eegSampleRate=250`、`imuSampleRate=50`；`emg/ecg/brth/ppg/spo2/mag/angle/gest=0`。`modelName` 固件上报 `OB6000` 属已知现象，不作 FAIL。
- **有效性说明**：能力字段是数据流/参数用例的判定依据，必须可靠；偏离 spec 即 FAIL。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试

- **预期结果**：不适用，记 SKIP；等价行为由 ASYNC-FUNC-002/010 覆盖。
- **有效性说明**：Python 专属 API，Android 无对应实现。
- **可自动化**：auto（无需设备）
- **人工介入**：无
- **测试结果**：待测试
