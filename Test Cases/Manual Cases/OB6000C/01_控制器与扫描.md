# OB6000C 控制器与扫描用例（CTRL-*）

> 适用对象：OB6000C（MAC `78:1C:9D:E4:6C:6B`，identity `6C6B`）。
> Android 侧 `SensorController` 为单例：`SensorController.getInstance()`；`terminate()` 为**静态方法**。
> 蓝牙为 Android 原生 BLE，初始化时调 `registerBleBridge(context)`；**无 dongle、无后端切换**。

### CTRL-FUNC-001 蓝牙未开启时 isEnable==False，startScan 被拒绝
- **优先级**：P0
- **测试目的**：验证控制器感知蓝牙状态并在关闭时拒绝扫描。
- **流程与逻辑**：`registerBleBridge(context)` 后，人工关闭系统蓝牙 → 读 `isEnable()` → 调 `startScan(3000)`，再用 `scan(3000)`（suspend 扩展）观察返回值；读 `isScanning()`。
- **预期结果**：`isEnable()==false`；`startScan` 不进入扫描态，`isScanning()==false`；`scan` 返回空列表或被拒绝（记录实际返回值），不崩溃。
- **有效性说明**：若蓝牙关闭仍能「成功扫描」，说明 SDK 未校验硬件使能，属缺陷。
- **可自动化**：semi-auto
- **人工介入**：人工关闭系统蓝牙（设置页或快捷开关），并在提示窗口内完成。
- **测试结果**：待测试

### CTRL-FUNC-004 scan/scanOnce 返回设备列表并发现 OB6000C
- **优先级**：P0
- **测试目的**：验证单次扫描发现 OB6000C。
- **流程与逻辑**：调 `scan(5000)`（suspend 扩展，返回 `List<BleDevice>`）；遍历结果，检查 `name` 以 `OB6000C` 开头、`mac` 形如 `XX:XX:XX:XX:XX:XX`、`rssi` 在合理范围（如 `-100..0`）。可另用 `scanOnce(5000, OnScanResultListener)` 复核回调式入口。
- **预期结果**：返回非空列表，含至少一台 `name` 前缀 `OB6000C` 的设备；其 `mac` 与登记值 `78:1C:9D:E4:6C:6B` 一致（或 identity 后四位 `6C6B` 命中）。
- **有效性说明**：稳定发现设备是连接前置；`BleDevice` 的 `name/mac/rssi` 为 public final 字段。
- **可自动化**：auto
- **人工介入**：无（需设备开机在扫描范围内）
- **测试结果**：待测试

### CTRL-FUNC-007 requireSensor 有效/无效
- **优先级**：P0
- **测试目的**：验证由扫描结果或 MAC 创建 `SensorProfile`。
- **流程与逻辑**：对扫描到的 OB6000C 调 `requireSensor(bleDevice)`；再对同一 MAC 调 `requireSensor("78:1C:9D:E4:6C:6B")`。无效场景：Kotlin 侧入参为非空 `String`，用空串 `""`、非法 MAC `"ZZ:ZZ:ZZ:ZZ:ZZ:ZZ"`、未扫描到的合法格式 MAC 分别调用，观察返回。
- **预期结果**：有效设备/MAC 返回非空 `SensorProfile`（重复调用返回同一实例或等价实例）；空串/非法 MAC 返回 `null`，不崩溃、不抛异常。
- **有效性说明**：设备句柄创建正确性；Android 方法签名不接受 `None`，故以空串/非法 MAC 覆盖空值等价类。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试

### CTRL-BND-001 startScan(periodInMs) 6 点边界
- **优先级**：P1
- **测试目的**：验证扫描周期参数边界。
- **边界定义（依据）**：AAR 签名为 `boolean startScan(int periodInMs)`，入参为 Java `int`，上限 `Int.MAX_VALUE = 2147483647`。`MAX+1` 在 Kotlin 中无法用 `Int` 表达，用 `Int.MAX_VALUE + 1` 溢出为 `Int.MIN_VALUE = -2147483648` 覆盖越界等价类。
- **流程与逻辑**：分别传 `0、1、Int.MAX_VALUE-1、Int.MAX_VALUE、-1、Int.MIN_VALUE`（即 MAX+1 溢出值），记录返回值、`isScanning()` 与是否抛异常；每点之间 `stopScan()` 复位。
- **预期结果**：合法值（`1`、`MAX-1`、`MAX`）不崩溃并返回可解释结果（`true`/`false` 均记录，`false` 可能因蓝牙未开启或周期不合法）；非法值（`0`、`-1`、`Int.MIN_VALUE`）返回 `false` 或不进入扫描态，**不得崩溃/ANR**；任一边界值导致进程崩溃判 FAIL。
- **有效性说明**：参数边界健壮性；Android 为 Java `int` 入参，不要求像 Python 一样抛 `ValueError`，以「不崩溃 + 状态正确」为判定核心。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试
