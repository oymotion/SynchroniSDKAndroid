# OB6000C 电量/日志/调试用例（BATT-* / LOG-*）

> 电量：`getBatteryLevel()`（suspend 扩展，返回 `Int`，无有效读数 `-1`）、`getCachedPower()`、`getBatteryLevelSync()`；回调 `setOnPowerListener { profile, level -> }`。
> 日志：Android 无 `setDebugEnabled()` / `setLogPath()` 方法，改由 **controller 级 `setParam`** 控制：
> `controller.setParam("DEBUG_ENABLED","True")`、`controller.setParam("LOG_PATH", dir)`、`controller.setParam("LOG_PATH","True"/"False")`、`controller.setParam("DATA_LOG_ENABLED","True")`；
> profile 级日志用 `profile.setParam("DEBUG_LOG_PATH","True"/绝对路径)`。默认日志目录 `/sdcard/Documents/sensorsdklog`。

## 电量（BATT-*）

### BATT-FUNC-001 getBatteryLevel 返回 0~100（或 -1）
- **优先级**：P1
- **测试目的**：验证电量读取。
- **流程与逻辑**：READY 后调 `getBatteryLevel()`（suspend，返回 `Int`）；再读 `getCachedPower()` 对照。
- **预期结果**：返回 0~100；无有效读数返回 -1（不判失败，仅记录）；`getCachedPower()` 与最近一次有效读数一致或为 -1。
- **有效性说明**：电量接口可用；`-1` 表示未知，不是错误。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试

### BATT-FUNC-002 onPowerChanged 上报 0~100，±2% 滞回，不报 -1
- **优先级**：P1
- **测试目的**：验证电量回调。
- **流程与逻辑**：注册 `setOnPowerListener`，观察上报值（可改变功耗/等待电量变化）。
- **预期结果**：上报 0~100；1% 抖动被过滤（±2% 滞回）；不报 -1。
- **有效性说明**：回调稳定性。
- **可自动化**：semi-auto
- **人工介入**：人工制造电量变化或长时间观察。
- **测试结果**：待测试

### BATT-FUNC-003 powerRefreshInterval 决定上报周期
- **优先级**：P1
- **测试目的**：验证刷新周期。
- **流程与逻辑**：`init(packageSampleCount, timeoutMs, powerRefreshIntervalMs)` 分别设 `1000` 与 `5000`，统计 `setOnPowerListener` 相邻回调间隔（≥5 个间隔取中位数）。
- **预期结果**：回调周期与设置值同量级（允许 ±20% 调度抖动）；两次设置能观察到周期差异。
- **有效性说明**：周期参数生效；第三参数为毫秒。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试

### BATT-FUNC-004 startDataNotification 起流期间 onPowerChanged 持续回调
- **优先级**：P1
- **测试目的**：验证起流后 `setOnPowerListener` 不会停止回调（针对「起流一段时间后电量回调静默」的失效模式）。
- **流程与逻辑**：
  1. 连接 → READY → `init(20, 30000, 1000)`（电量刷新周期设小值 1000ms，便于短时间观察）。
  2. 注册 `setOnPowerListener`，记录每次回调到达时间戳（不关注电量值是否变化）。
  3. `startDataNotification()` 起流（EEG）。
  4. 起流后持续观察 ≥10 分钟，统计相邻回调间隔。
- **预期结果**：起流期间回调按 `powerRefreshIntervalMs` 周期持续到达；观察窗口内任意相邻回调间隔 ≤ 5×`powerRefreshIntervalMs`（线程调度/系统抖动容错上限），直到窗口结束无静默。
- **有效性说明**：覆盖「起流后电量回调停止」的失效模式；判定基于「事件是否持续到达」，不受 ±2% 滞回导致电量值长时间不变的影响。
- **可自动化**：auto（起流后无需人工动作）
- **人工介入**：无
- **测试结果**：待测试

## 日志/调试（LOG-*）

### LOG-FUNC-001 DEBUG_ENABLED 开关 controller log
- **优先级**：P1
- **测试目的**：验证调试日志开关。
- **流程与逻辑**：`controller.setParam("DEBUG_ENABLED","True", null)` → 观察日志目录生成控制器日志文件并按预期增长 → `controller.setParam("DEBUG_ENABLED","False", null)` → 观察停止写入。
- **预期结果**：`True` 时创建/写入 log，返回 `"OK"`；`False` 后新增内容停止（先等 ~2s 刹车，再观察 ~5s 增量）。
- **有效性说明**：Android 无 `setDebugEnabled()` 方法，等价键为 controller 级 `DEBUG_ENABLED`。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试

### LOG-FUNC-002 LOG_PATH 目录/已存在文件
- **优先级**：P1
- **测试目的**：验证日志路径。
- **流程与逻辑**：`controller.setParam("LOG_PATH", dir)`（不存在的目录）→ 确认目录被创建；再传一个**已存在的文件路径** → 观察写入行为与文件原内容；`LOG_PATH="True"` 恢复默认目录，`LOG_PATH="False"` 关闭文件输出。
- **预期结果**：目录不存在时自动创建并返回 `"OK"`；传入已存在文件路径返回 `"OK"`，按**追加**语义写入日志，原内容保留为前缀、不被截断或清空，不崩溃（**追加是期望的逻辑**）；`True`/`False` 语义正确。
- **有效性说明**：路径校验以「目录自动创建 + 文件路径追加不丢原内容」为准；Android 用 controller 级 `LOG_PATH`，不是 `setLogPath(True, dir)`。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试

### LOG-FUNC-003 DEBUG_LOG_PATH=True 生成 profile log
- **优先级**：P1
- **测试目的**：验证设备级日志。
- **流程与逻辑**：`profile.setParam("DEBUG_LOG_PATH","True")` → `profile.getParam("DEBUG_LOG_PATH")` 读回 → 连接/起流产生日志 → 检查 SDK 日志目录中该设备的 profile 日志文件。
- **预期结果**：设置返回 `"OK"`；回读表示已启用（`True` 或具体路径）；生成 profile log 且路径可读；`"False"`/`""` 可关闭。
- **有效性说明**：每设备日志；也可传绝对路径导出到指定位置。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试

### LOG-FUNC-004 早期 scan/connect 日志不丢失
- **优先级**：P1
- **测试目的**：验证日志开启顺序与早期日志完整性。
- **流程与逻辑**：按 Android 约定顺序：`controller.setParam("LOG_PATH", dir)` → `controller.setParam("DEBUG_ENABLED","True")` → `registerBleBridge(context)` → scan → connect；检查日志文件中是否包含 scan/connect 阶段记录。再对比一次「先 scan/connect、后开日志」的对照组。
- **预期结果**：按正确顺序开启时，scan/connect 早期日志完整落盘；反序时早期日志缺失属预期（Android 日志文件在启用时打开，无 Python 的缓冲回放机制），记录实际行为即可，不判缺陷。
- **有效性说明**：日志完整性；Android 开发文档明确要求 `LOG_PATH` 在 `DEBUG_ENABLED=True` 之前、两者在 `registerBleBridge` 之前。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试

### LOG-FUNC-005 log(msg, level) 写入应用日志
- **优先级**：P1
- **测试目的**：验证应用日志接口。
- **流程与逻辑**：`controller.log("ctrl-app-log","I")`、`profile.log("profile-app-log","W")`，level 分别试 `D/I/W/E`，在 logcat 与 SDK 日志文件中检索。
- **预期结果**：日志正确写入并带 `[App]` 标记；`D` 受 `DEBUG_ENABLED` 控制，`I/W/E` 始终输出；profile 未启用（`DEBUG_LOG_PATH=False`）时回退到 controller log。
- **有效性说明**：应用日志正确；查看方式 `adb logcat -s System.out` 或 SDK 日志文件。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试

### BATT-FUNC-005 getCachedPower 返回缓存电量且不发起新请求
- **优先级**：P1
- **测试目的**：验证缓存电量读取快速、可用，且不会因频繁调用触发额外 BLE 请求。
- **流程与逻辑**：连接后先读取一次真实电量建立缓存 → 连续调用 `getCachedPower()` 多次，记录返回与耗时；对比 `getBatteryLevel()`。
- **预期结果**：缓存值与最近一次真实电量一致（允许刷新周期内差异）；调用不阻塞；不崩溃。
- **有效性说明**：UI 高频刷新电量应走缓存接口，避免 BLE 拥塞。

- **人工介入**：无
