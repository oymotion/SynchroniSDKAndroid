# OB6000C 参数用例（PARAM-*）

> 能力基线唯一来源：`Test Cases/Automation/device_specs/OB6000C.json`。OB6000C 核心参数为 `EEG_SAMPLE_RATE`（固定 250）。
> Android 接口：`setParam(key, value)` / `getParam(key)` 为 **suspend 扩展**（返回 `String`），成功只认 `"OK"`；以 `Error` / `Not supported` / `<` 开头视为被拒绝。
> 流开关 key 与 `DataType` 枚举名不是一回事：权威 key 列表取自 `getParam("NTF")`（返回如 `NTF_EEG|ON|NTF_IMPEDANCE|ON|…`）。

### PARAM-FUNC-001 每个 NTF_* 键 ON/OFF 返回 OK，getParam 一致
- **优先级**：P0
- **测试目的**：验证数据流开关。
- **流程与逻辑**：先 `getParam("NTF")` 取权威开关列表；对 OB6000C 适用键（`NTF_EEG`、`NTF_IMPEDANCE`、`NTF_IMU`、四路独立 IMU 子流开关）逐一 `setParam(key,"ON")` / `setParam(key,"OFF")`，每次后 `getParam("NTF")` 核对。不支持的流键（EMG/GEST/ECG/BRTH/PPG/SpO2/MAG/ANGLE）不执行，按 spec 记 SKIP。
- **预期结果**：支持的键返回 `"OK"`，`getParam("NTF")` 状态一致；不支持键若被调用应返回 `Not supported`/`Error`，不崩溃。
- **有效性说明**：参数读写一致；**不要**用 `getParam("NTF_XXX")=="ON"` 判断能力，能力以 `DeviceInfo.*ChannelCount>0` 与 spec 为准。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试

### PARAM-FUNC-002 FILTER_* 键 ON/OFF

- **流程与逻辑**：`setParam("FILTER_50HZ"/"FILTER_60HZ"/"FILTER_HPF"/"FILTER_LPF","ON"/"OFF")`，`getParam("FILTER")` 核对；四项在 OB6000C 均支持。
- **预期结果**：四次均返回 `"OK"`；`getParam("FILTER")` 状态与设置一致。
- **有效性说明**：滤波参数生效；spec `filters` 四项均为 `true`，任一失败即 FAIL。
- **可自动化**：auto

### PARAM-FUNC-003 NTF_IMU 联动四个独立 IMU 子流
- **优先级**：P1
- **测试目的**：验证 IMU 主开关联动。
- **流程与逻辑**：保持 `NTF_EEG` 开启（`IMU_SAMPLE_RATE` 的 `coStream=NTF_EEG`）；`setParam("NTF_IMU","ON")` 后确认四路子流（ACC/GYRO/EULER/QUAT）在 `getParam("NTF")` 中同步为 ON，起流确认 `NTF_IMU` 13 通道；再 `setParam("NTF_IMU","OFF")` 确认四路同步关闭。
- **预期结果**：`NTF_IMU=ON` → 子流全 ON 且 IMU 流 13 通道；`NTF_IMU=OFF` → 子流全 OFF；不崩溃。
- **有效性说明**：OB6000C 实测支持聚合 IMU（13 通道），原「预计不支持」结论已作废；联动关系偏离即 FAIL。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试

### PARAM-FUNC-004 EEG_SAMPLE_RATE 设置与回读
- **优先级**：P0
- **测试目的**：验证 EEG 采样率设置（OB6000C 核心功能）。
- **流程与逻辑**：`getParam("EEG_SAMPLE_RATE_LIST")` 取档位（仅 `250`）→ 逐一 `setParam("EEG_SAMPLE_RATE", value)` → `getParam("EEG_SAMPLE_RATE")` 回读并起流实测。ECG 能力为 0，**不做 EEG/ECG 同写**（原 Python 用例的 ECG 部分在 OB6000C 不适用，记 SKIP）。
- **预期结果**：`setParam("EEG_SAMPLE_RATE","250")` 返回 `"OK"`；回读 `250`；实测采样率偏差 ≤5%。
- **有效性说明**：EEG 采样率是核心参数；单档位设备仍需验证设置闭环。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试

- **有效性说明**：查询接口正确；OB6000C 采样率固定 250。
- **可自动化**：auto

### PARAM-FUNC-007 起流中修改参数自动停流重起并生效
- **优先级**：P0
- **测试目的**：验证起流中改参。
- **流程与逻辑**：EEG 起流稳定后，起流中分别改 `FILTER_LPF`（ON→OFF）、`EEG_SAMPLE_RATE`（重设 250）；观察回调是否短暂中断后恢复、`isDataTransfering()` 变化，以及新状态是否在 `getParam` 中生效。
- **预期结果**：SDK 自动停流重起（或按设计即时生效）；新参数生效；数据恢复且 `getDataType()` 仍为 EEG；不崩溃。
- **有效性说明**：动态配置能力；**不要通过关闭 `NTF_EEG` 验证**——`NTF_IMPEDANCE` 与 `NTF_IMU` 的 `coStream` 都是 EEG，关闭 EEG 会连带停流，属预期联动而非缺陷。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试

### PARAM-FUNC-010 DEBUG_BLE_DATA_PATH / DEBUG_LOG_PATH
- **优先级**：P1
- **测试目的**：验证调试落盘开关。
- **流程与逻辑**：`setParam("DEBUG_BLE_DATA_PATH","True")` → `getParam("DEBUG_BLE_DATA_PATH")` → `setParam("DEBUG_BLE_DATA_PATH","False")`；`setParam("DEBUG_LOG_PATH","True")` → `getParam("DEBUG_LOG_PATH")` → 关闭。随后起流一段时间，确认 bin/日志按开关落盘或停止。
- **预期结果**：两次开关均返回 `"OK"`，回读状态一致；开启时生成 bin / 日志文件，关闭后不再新增。

- **可自动化**：auto

### PARAM-BND-001 setParam 非法 value
- **优先级**：P1
- **测试目的**：验证非法值处理。
- **流程与逻辑**：对代表性键（`NTF_EEG`、`NTF_IMPEDANCE`、`NTF_IMU`、`FILTER_50HZ`、`FILTER_LPF`、`EEG_SAMPLE_RATE`）逐一传空串、`"on"/"off"`（小写）、`"TRUE"/"FALSE"`、`"1"/"0"`、`"INVALID"`、`"null"`。Kotlin 入参为非空 `String`，无法传 `null`；如需覆盖 Java 侧 `null`，由 Java 调用方单测并预期 `NullPointerException`/被拒绝，本用例以空串等价覆盖。
- **预期结果**：非法值被拒绝/返回 `Error`；合法大小写形式是否接受按 SDK 实际记录（若接受小写则记录，不作 FAIL）；不崩溃、参数值不被破坏。
- **有效性说明**：输入校验；`None` 在 Kotlin 侧不存在，改用空串/`"null"` 覆盖空值等价类。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试
