# OB6000C 数据流用例（DATA-*）

> 能力基线唯一来源：`Test Cases/Automation/device_specs/OB6000C.json`，运行时以 `getDeviceInfo()` 的 `*ChannelCount > 0` 判定（**不用** `getParam("NTF_XXX")=="ON"` 判定支持）。
> OB6000C 支持：`NTF_EEG` 32 通道（核心）、`NTF_IMPEDANCE` 32 通道（约 1Hz，需与 EEG 同起）、`NTF_IMU` 13 通道（acc3+gyro3+euler3+quat4）、`NTF_GFORCE_ACC/GYRO/EULER/QUAT` 独立开关。
> 不支持：EMG / GEST / ECG / BRTH / PPG / SpO2 / 磁力计 / 角度（通道数 0）→ 记录 SKIP。
> 关键口径：**统计与读值前先按 `getDataType()` 分流**；各流 `channelIndex` 是独立编号空间，不能跨流混算。`getImpedance()` 只有 `NTF_IMPEDANCE` 样本有效，其它流为无意义的 0。

### DATA-FUNC-001 init(packageSampleCount, timeoutMs, powerRefreshIntervalMs) 成功，hasInited==True
- **优先级**：P0
- **测试目的**：验证 init 成功。
- **流程与逻辑**：READY 后调 `init(20, 30000, 1000)`（suspend 扩展，参数依次为每包样本数 / 超时 / 电量刷新周期），读返回值与 `hasInited()`。
- **预期结果**：返回 `true`，`hasInited()==true`。
- **有效性说明**：init 是起流前置；Android 扩展签名与 Python `init(packageSampleCount, powerRefreshInterval)` 参数顺序不同，以 `packageSampleCount, timeoutMs, powerRefreshIntervalMs` 为准。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试

### DATA-FUNC-005 各 DataType 流能收到对应 SensorData（按 spec 硬断言）
- **优先级**：P0
- **测试目的**：验证 OB6000C 支持/不支持的数据流类型与 spec 一致。
- **流程与逻辑**：
  1. 从 `getParam("NTF")` 读取权威流开关列表（各键带 ON/OFF），按需 `setParam(<key>,"ON")`；spec 流键只用于匹配 `getDataType()`。
  2. 分两组起流验证：EEG（`NTF_EEG`，32 通道）、EEG+IMPEDANCE（`NTF_IMPEDANCE` 32 通道，必须与 EEG 同起）、EEG+IMU（`NTF_IMU` 13 通道）、EEG+四路独立 GFORCE 流（ACC3/GYRO3/EULER3/QUAT4）。
  3. 统计回调中出现的 `DataType` 集合与各流 `getChannelCount()`；对 spec 标 `supported=false` 的流检查是否意外产出数据。
- **预期结果**：spec 标支持的流均收到数据且通道数一致（EEG=32、IMPEDANCE=32、IMU=13、ACC=3、GYRO=3、EULER=3、QUAT=4）；spec 标不支持的流（EMG/GEST/ECG/BRTH/PPG/SpO2/MAG/ANGLE）**不得产出数据**；偏离即 FAIL。
- **有效性说明**：逐模态验证真实能力，避免遗漏/误判；`NTF_IMU` 与 GFORCE 四路是不同流，需分别统计。
- **可自动化**：auto（能力判定自动）
- **人工介入**：无
- **测试结果**：待测试
