# OB6000C 异步接口用例（ASYNC-*）

> Android AAR 的「异步」有三种形态，本文件按等价关系映射，不照搬 Python asyncio：
> 1. **Kotlin suspend 扩展**：`SensorController.scan(timeoutMs)`、`SensorProfile.connect()/disconnect()/init()/startDataNotification()/stopDataNotification()/setParam()/getParam()/getBatteryLevel()/fetchDeviceInfo()`、`multiStartDataNotification()/multiStopDataNotification()`、`parseBinToCsvAsync()`；
> 2. **`CompletableFuture`**：`connectAsync()` / `disconnectAsync()`；
> 3. **回调 Listener**：`OnCompletionListener` / `OnParamListener` / `OnBatteryListener` / `OnScanResultListener` / `OnMultiResultListener`。
> Python 的「事件循环内同步接口被拒绝」限制在 Android 不存在；Android 全部操作本身非阻塞，suspend 只是回调的协程封装。
> `ASYNC-FUNC-011/012` 需 ≥2 台；缺设备则 SKIP。

### ASYNC-FUNC-001 asyncScan 返回设备列表
- **优先级**：P0
- **测试目的**：验证异步扫描。
- **流程与逻辑**：`val list = controller.scan(5000)`（suspend），遍历结果检查是否含 OB6000C；与同步回调式 `startScan` + `setOnScanResultListener` 的结果比对。
- **预期结果**：返回 `List<BleDevice>`，含 OB6000C（MAC `78:1C:9D:E4:6C:6B` 或 identity `6C6B`），与回调式扫描结果一致。
- **有效性说明**：异步扫描链路正确。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试

### ASYNC-FUNC-010 suspend / CompletableFuture / 回调混用行为明确
- **优先级**：P1
- **测试目的**：验证不同异步形态混用/重复调用时的边界行为，避免误用导致状态错乱。
- **流程与逻辑**：
  1. 连接阶段：先调 `connectAsync()` 并**不等待**完成，立即调 suspend `connect()`；记录两者返回、耗时与最终 `getDeviceState()`。
  2. 断开阶段：先 `disconnectAsync()` 不等待，立即调 `disconnect()`；记录状态。
  3. 参数阶段：suspend `setParam` 与回调式 `setParam(..., listener)` 并发下发同一键；记录最终 `getParam` 值。
  4. 最后用「单一形态、顺序调用」重走连接-断开，核对状态迁移正确。
- **预期结果**：重复/并发连接不导致卡死、崩溃或状态倒退；第二次调用返回 `false`/受控异常（记录实际行为）；并发设参最终值确定且与最后一次成功下发一致；纯顺序路径状态迁移正确。
- **有效性说明**：Android 无「事件循环内同步接口被拒绝」限制（Python 专属），本用例改为验证同一底层操作的多种封装重复/并发调用是否幂等、无状态错乱；如实记录不判为「无冲突」。
- **可自动化**：auto
- **人工介入**：无
- **测试结果**：待测试
